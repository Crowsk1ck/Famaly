# Discord outbox v13 — безпечний порядок увімкнення

Цей реліз додає **опціональну** D1-чергу `discord_outbox` та заплановане виконання кожні 2 хвилини.

## До застосування міграції
- Доставка продовжує використовувати попередню схему `waitUntil`.
- `DISCORD_OUTBOX_ENABLED` має бути **відсутнім** або не дорівнювати `true`.
- Фоновий cron нічого не робить за вимкненого прапорця.
- Фінанси, контракти, користувачі та R2 не зачіпаються.

## Увімкнення на production
1. Через GitHub Actions → **GRIZZLY D1 migrations (manual)** → `inspect` перевірити, що нова `0008_discord_outbox.sql` очікує застосування.
2. Підтвердити резервну копію D1 та відсутність невідомих фундаментальних міграцій.
3. Запустити **GRIZZLY D1 migrations (manual)** з `operation=apply` та `confirm_database=grizzly-db`. Це окрема явна операція, не частина Worker deploy.
4. Перевірити `wrangler d1 migrations list grizzly-db --remote`.
5. Лише після успішної міграції в Cloudflare Worker `famaly` встановити `DISCORD_OUTBOX_ENABLED=true`.
6. Увійти як лідер, перевірити «Налаштування → Discord» та виконати тестову доставку. Далі слідкувати за журналом.

## Гарантії та межі
- Черга зберігає тип події, маршрут і мінімальні дані повідомлення, **без webhook-токенів**.
- Запис `pending` атомарно захоплюється одним виконавцем. Після завершення — `sent` або `failed`.
- Явну помилку Discord `HTTP 429` можна безпечно повторити пізніше (максимум три спроби загалом).
- Мережеві помилки з невідомим результатом та перервані `sending` позначаються `uncertain`: **автоматично повторно не відправляються**, щоб уникнути дублювання.
- Нові події додаються до черги асинхронно після успішної прикладної дії. Це **не транзакційний outbox**: збій Worker до виконання `waitUntil` все ще може пропустити створення запису. Для строгих гарантій потрібне атомарне внесення події разом із прикладною транзакцією і визначений ключ ідемпотентності.
- Обробка `uncertain` потребує ручного звірення з каналом Discord. Автоматичний «повторити все» заборонений.
- Не можна встановлювати `DISCORD_OUTBOX_ENABLED=true` **до міграції**; інакше фонове збереження повідомлень не працюватиме.

## Відкат
При непередбаченій проблемі прибрати `DISCORD_OUTBOX_ENABLED` або встановити `false`.
Worker повернеться до попередньої доставки. Таблицю `discord_outbox` не видаляти —
її можна розібрати після відновлення, без втрати діагностичних даних.
